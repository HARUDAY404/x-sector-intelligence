# X Sector Intelligence｜X 赛道情报

把 X 上零散、重复、夹杂推广的信息，整理成一份**可追溯、可判断、能导向行动**的分层情报简报。

这不是一个“热门账号排行榜”，也不是把几十条帖子压缩成另一种信息流。它更关心：今天真正发生了什么？哪些只是作者观点或商业叙事？证据是否可靠？这条信息对当前目标有什么参考价值？是否值得转化成一次实验？

## 为什么做这个 Skill

刷信息流很容易形成这样的循环：

```text
看到新观点 → 感到有启发 → 收藏 → 继续刷
```

问题不在信息太少，而在于信息没有被定位、连接和使用。一个帖子还可能同时混合产品发布、个人判断、单点案例和课程推广；多个账号转发同一消息，也不等于出现了多份独立证据。

`x-sector-intelligence` 因此采用一套证据导向的处理方式：

```text
发现候选信源
    ↓
验证身份与活跃度
    ↓
区分事实、观点、推断、案例、推广
    ↓
寻找原始来源并交叉验证
    ↓
按可信度与参考价值评分
    ↓
只保留会改变判断或行动的内容
```

## 核心能力

- 分层追踪一手信源、中文头部/腰部作者、企业实践者、独立开发者和同阶段样本。
- 去除无独立信息的回复、互动诱饵、纯娱乐内容和重复搬运。
- 对同一事件去重，保留原始来源，并比较不同作者增加了什么解释。
- 将内容标记为 `事实`、`观点`、`推断`、`案例` 或 `推广`。
- 分别给出 1–5 分的可信度和参考价值，不用粉丝量或认证标识代替证据判断。
- 在安静的日子输出短报告，不为了“日报感”硬凑内容。
- 每月复查观察池，根据真实信息贡献建议升级、降级或移除账号。

## 情报结构

默认日报按以下层次组织：

1. **一手信源与标杆**：官方发布、研究、基础解释和长期战略变化。
2. **中文头部/腰部**：产品实践、企业交付、增长与商业化解释。
3. **同阶段实践者**：更接近普通创作者或独立开发者资源条件的实验、失败和进展。
4. **交叉验证与分歧**：不同来源的共识、冲突，以及尚未证实的重复说法。
5. **今日行动**：最多三个值得执行的动作；没有必要就省略。

每条保留内容包含：作者、核心主张、内容分类、证据说明、可信度、参考价值、为什么重要，以及可用时的原帖或一手来源链接。

报告结尾还会列出：

- **可以忽略**：重复、低信号或不值得投入时间的主题。
- **等待你一起判断**：最多三个仍有歧义、值得共同讨论的命题。

## 评分不是“拍脑袋”

### 可信度（1–5）

综合判断信源与事实的距离、证据完整度、可复现性、是否存在独立交叉验证，以及作者的利益冲突。只有作者单方面陈述时，会明确标注“仅见作者陈述”。

### 参考价值（1–5）

判断它是否与当前研究方向相关，以及是否足以改变一个决定、实验或行动。一个事实可以很可靠，但对你当下没有用；一个案例也可以很有启发，但不能自动推广成普遍规律。

## 观察名单的正确用法

[`references/watchlist.md`](references/watchlist.md) 是可维护的起始观察池，不是经过永久认证的“必关注名单”。其中既有官方和长期一手作者，也有来自个人关注、收藏、引用网络和主题扩展的候选账号。

更稳妥的准入流程是：

1. 验证用户名、身份和近期活跃状态。
2. 审计最近 30–50 条内容。
3. 检查主题相关性、原创率、证据质量、有效内容比例和推广比例。
4. 将候选账号放入 14 天试读池。
5. 根据它在日报中提供的独特信息升级或淘汰。

一句话原则：

> 榜单负责发现，内容审计负责准入，日报贡献负责留存。

使用前请按自己的研究目标修改观察名单。没有必要真的在 X 上关注名单中的所有账号，Skill 本身也不会自动关注、取消关注、点赞或转发。

## 安装

将仓库克隆到 Codex 的个人 Skills 目录：

```bash
git clone https://github.com/HARUDAY404/x-sector-intelligence.git ~/.codex/skills/x-sector-intelligence
```

重新启动 Codex，或开启一个新任务，让 Skill 被重新发现。

你也可以把仓库放在其他位置，再将整个 `x-sector-intelligence` 目录复制到 `~/.codex/skills/`。

## 使用示例

直接说：

```text
使用 $x-sector-intelligence，检查观察名单过去 24 小时的新内容，生成今天的分层情报简报。
```

也可以指定一个判断目标：

```text
使用 $x-sector-intelligence，重点分析最近 7 天关于企业 AI 落地与 FDE 的讨论。
区分事实、案例和推广，并告诉我哪些结论值得设计实验验证。
```

或拿一条具体内容共同判断：

```text
使用 $x-sector-intelligence 分析这条帖子：它说的是事实、观点、推断、案例还是推广？
证据缺口是什么？可信度和对我的参考价值分别是多少？
```

## 配合每日自动任务

Skill 定义判断框架，定时任务负责周期性运行。可在 Codex 中创建每日任务，并使用类似提示词：

```text
每天读取并监控 x-sector-intelligence skill 中的 X 博主观察名单，汇总过去 24 小时的新内容。排除成人与纯娱乐内容；按“一手信源与标杆、中文头部/腰部、同阶段实践者”分层。对每条重要内容标注事实、观点、推断、案例或推广，给出可信度 1–5、参考价值 1–5，并附原帖链接和必要的交叉验证来源。输出今日总览、分层摘要、分歧与风险、最值得精读的内容、可执行动作和观察名单维护建议。若当天没有有价值的新内容，保持安静，不发送无意义更新。
```

定时任务不会随仓库安装自动创建，需要在你自己的 Codex 环境中单独配置。若访问 X 需要登录，应使用你已有的登录会话；不要把 Cookie、Token 或其他凭据写入 Skill、提示词或仓库。

## 从信息到行动

这个 Skill 最终服务的不是“知道更多”，而是下面的闭环：

```text
每日发现信号
    ↓
每周选择一个真实问题
    ↓
做一个可验证的小实验
    ↓
记录结果、失败与适用边界
    ↓
形成判断、案例、模板、服务或产品
```

推荐把输出映射到这条价值链：看懂变化 → 学会能力 → 做出成果 → 解决问题 → 获得用户 → 完成付费 → 重复交付。新闻由日报帮助消化，真正值得公开积累的是实践证据。

## 边界与限制

- X 的公开页面、登录状态和接口可用性会影响抓取完整度。
- 本项目不承诺覆盖观察池中每一条帖子，也不把作者自述自动视为事实。
- 账号名单和内容质量会随时间变化，需要持续复核。
- 本项目不执行关注、取消关注、点赞、转发或发帖等账号操作。
- 输出是研究与决策辅助，不构成投资、法律、医疗或其他专业意见。

## 适合谁

- 想系统跟踪 AI、Agent、企业 AI、独立产品、内容增长和个人商业的人。
- 已经收藏很多内容，但难以形成稳定判断和行动的人。
- 希望建立个人信息源地图，而不是依赖平台推荐流的人。
- 想把“读过”推进到“验证过、做出来、获得反馈”的研究者和创作者。
